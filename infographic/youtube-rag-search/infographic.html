How YouTube RAG Search Works
Retrieval-Augmented Generation Pipeline — From Video to Searchable Knowledge
01
Fetch
yt-dlp downloads transcripts from tracked YouTube channels in batches of 50 videos. Date-windowed pagination handles full channel histories. A daily cron job automates the entire process.
yt-dlp 50 videos/batch daily-fetch.sh transcripts/*.md
02
Ingest
Transcripts are chunked by token count with overlap. Each chunk is embedded via OpenAI text-embedding-3-large into 1536-dimensional vectors, then stored in a local LanceDB database.
text-embedding-3-large 1536 dimensions LanceDB chunk + overlap
03
Query
The user's search query is embedded with the same model. LanceDB finds the most similar chunks via vector distance. Exponential time-decay boosts recent content: score = similarity × max(floor, 0.5^(age/half_life)).
semantic search vector similarity time decay scoring top-K results
04
Respond
Claude (Sonnet for routine queries, Opus for complex multi-transcript analysis) receives the top matching chunks and produces a formatted response with video title, date, URL, and relevant quotes.
Claude Sonnet / Opus title + date + URL relevant quotes
YouTube Channels → yt-dlp → Markdown → Embeddings → LanceDB → Query → Claude → Response
